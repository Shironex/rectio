## Install

```sh
pnpm dlx @rectio/cli add leave-requests
```

The item ships the list and the request form. The motion variant is `motion-leave-requests`; it
installs the plain block too.

## Usage

```tsx
import { LeaveRequests } from '@/components/blocks/people/leave-requests/leave-requests';

<LeaveRequests
  requests={requests}
  types={[
    { id: 'annual', label: 'Annual leave', allowance: 25 },
    { id: 'sick', label: 'Sick leave' },
  ]}
  holidays={holidays}
  onApprove={approve}
  onDecline={(request, reason) => decline(request, reason)}
/>;
```

A request is `{ id, person, type, start, end, halfStart?, halfEnd?, status, note?, decision? }`,
with `end` the day after the last day off. Its length counts working days only: weekends and
`holidays` take nothing off, and a half first or last day takes half a day.

Approving and declining both ask first; declining needs a reason. When a teammate is off on the
same working days, the row says who, and the approve step says on how many days. Pass `team` to
compare against requests other than the ones listed.

For a person's own leave, pass `balanceFor` with their id and `showPerson={false}`: the block shows
each type's balance (allowance, taken, waiting and left) above the list, and `onCancel` lets them
withdraw a request that has not started.

```tsx
import { LeaveRequestForm } from '@/components/blocks/people/leave-requests/leave-request-form';

<LeaveRequestForm
  types={types}
  personId={me.id}
  requests={requests}
  minDay={today}
  onSubmit={(draft) => create(draft)}
/>;
```

Pick a type and a range in the calendar; half day boxes appear for the first and last day. The
preview says how many working days the range takes and what the balance will be after it, and
warns when a teammate is off too. The draft you receive has an exclusive `end` and the length in
`halves`. A range of weekend days, one over the balance, or one over the person's own pending or
approved leave (which would take the same days from the balance twice) is held back with the
reason, and the clash names the other request. A range must end after it starts: one that ends on
or before its start takes no days and is refused.

## Logic

`leaveHalves(span, calendar)`, `leaveBalances(types, requests, personId, calendar)`,
`leaveOverlaps(span, team, options)`, `ownLeaveOverlaps(span, requests, personId)`,
`leaveProblem(span, balance, calendar, own)` and `spanFromPicked(from, to)` run on the server too.

A decision acts on the request as it is when you confirm. If it was decided or cancelled while the
dialog was open, confirming closes the dialog without acting. See
[Confirming](/docs/blocks/people#confirming) and
[Rendering on the server](/docs/blocks/people#rendering-on-the-server).

## Accessibility

- Every action button names the person, the type and the dates, so a list of Approve buttons
  reads apart.
- The confirm dialogs put the focus on the safe answer; a missing reason is said aloud.
- The form's preview is a polite live region, and the calendar's days are buttons named by their
  full date. The half day boxes are labelled checkboxes.
