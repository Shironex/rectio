The `rectio` command copies registry items into your project and keeps track of them. It needs
Node 22.12 or later. Start with:

```sh
pnpm dlx @rectio/cli init
```

In a terminal, `init` asks what you want: rectio in the app you are in, or a new app from a
template. Every answer is also a flag, so scripts and CI run the same command with no questions.

The commands below write `rectio` for short. Run them through `pnpm dlx @rectio/cli` (or
`npx @rectio/cli`), or install the CLI globally with `pnpm add -g @rectio/cli` to type `rectio`.
The commands the CLI itself suggests (in the summary box, hints and errors) follow how you started
it: `pnpm dlx @rectio/cli add <item>` after a `pnpm dlx` run, `rectio add <item>` after a global
install.

## Commands

### init

Sets up a project: detects the framework, checks Tailwind v4, finds the CSS entry and the import
alias, writes `rectio.json`, and installs `tokens`, a theme and `cn`.
[Installation](/docs/installation) walks through it.

Run in a terminal with no deciding flag, `init` first asks how to start:

- **Add rectio to this project**, offered when the folder has a `package.json`, with what it
  detected (`Vite, Tailwind 4.3.5`). It then confirms the framework, the CSS entry and the import
  aliases (you can edit each alias), asks for the theme, and offers a starter set of components
  (button, field, select, dialog, card, badge, tabs, data-table, money) or none.
- **Start a new app from a template**: pick a template (type to filter), a folder, the theme, the
  package manager (the detected one first), whether to install now, and whether to create a git
  repo with a first commit (asked only when git is on your PATH and the folder is not already
  inside a repo). Preview the templates at
  [shironex.github.io/rectio/templates](https://shironex.github.io/rectio/templates).

The theme is `default` (light and dark), or a theme URL from the
[theme generator](/docs/theming/generator). A one-line recap follows, then the same steps and summary as the
flag forms. Arrow keys or `j` and `k` move, space toggles in a list of checkboxes, Enter answers,
and Ctrl+C or Esc stops with exit code 130 and nothing written.

```sh
rectio init [--theme <id>] [--css src/index.css] [--framework vite|next|tanstack-start]
            [--registry <url|folder>] [--pm pnpm|npm|yarn|bun] [--force] [--dry-run]
            [--no-install] [-y]
```

| Flag                 | What it does                                                          |
| -------------------- | --------------------------------------------------------------------- |
| `-y`, `--yes`        | Ask nothing and take every default: rectio in this project.           |
| `--theme <id>`       | Theme to install, or a theme generator link. Defaults to `default`.   |
| `--css <path>`       | The CSS file that imports Tailwind. Implies this project, no prompts. |
| `--framework <name>` | `vite`, `next` or `tanstack-start`. Implies this project, no prompts. |
| `--pm <name>`        | `pnpm`, `npm`, `yarn` or `bun` instead of the detected one.           |
| `--force`            | Rewrite `rectio.json` even if it exists.                              |
| `--dry-run`          | Show the plan, write nothing.                                         |
| `--no-install`       | Add packages to `package.json` without running the install.           |

#### When init asks

| Run                                                   | Questions                                      |
| ----------------------------------------------------- | ---------------------------------------------- |
| `init` in a terminal                                  | yes, minus any a flag answers                  |
| `init --yes`, `init -q`                               | none: rectio in this project with the defaults |
| `init --css ...` or `init --framework ...`            | none: rectio in this project                   |
| `init --template <name> [folder]`                     | none, as before                                |
| stdin or stdout not a terminal, `CI` set, `TERM=dumb` | none: the defaults, as before                  |
| `init --yes` with no `package.json`                   | none: fails and asks for `--template <name>`   |
| `rectio mcp`                                          | never                                          |

Running `init` again with another `--theme` installs that theme and records it in `rectio.json`.

### init --template

Starts a new project from a [template](/docs/templates): a complete Next.js app you own from the
first commit.

```sh
rectio init --template finance-app [folder] [--theme <id>] [--registry <url|folder>]
            [--pm pnpm|npm|yarn|bun] [--git | --no-git] [--force] [--dry-run] [--no-install]
```

`--pm` picks the package manager for the install. `--git` creates a git repo with a first commit
after the install (with a default `.gitignore` when the template has none); a missing git identity
leaves the repo without a commit and says so. A folder that is not empty stops the run unless you
pass `--force`.

1. Resolves the template and every kit item it uses, checks the key, then fetches and verifies all
   of them. A missing key or a failed download writes nothing.
2. Writes the template into `folder` (default: the template name), which must be empty unless you
   pass `--force`. The package name follows the folder name.
3. Writes `rectio.json` with `@/` aliases (the template's `tsconfig.json` maps `@/*` to the project
   root), then installs the kit items as `add` does: components under `components/ui`, blocks under
   `components/blocks`, helpers under `lib`, tokens and the theme under `styles/rectio`. The
   template's imports already point at those paths.
4. Records the kit items in `rectio.lock.json`, so `diff` and later updates work on them. The
   template's own files are yours and are not tracked.

`rectio list --templates` shows the templates with their category.

### add

Adds items and everything they depend on.

```sh
rectio add button dialog money [--overwrite] [--dry-run] [--no-install]
```

1. Resolves the dependency graph from the registry index. A cycle or an unknown item is named.
2. Fetches every item and checks its schema and its integrity hash.
3. Plans every write. A file you edited since rectio wrote it stops the whole add, and nothing is
   written, unless you pass `--overwrite`.
4. Writes the files with imports rewritten to your aliases, adds theme and style CSS to the managed
   block in your CSS entry, and records everything in `rectio.lock.json`.
5. Adds missing packages to `package.json` (ranges already there win) and runs the install of the
   package manager whose lockfile is nearest: pnpm, npm, yarn or bun. Without a lockfile it uses
   the `packageManager` field, then the manager that started the CLI (`pnpm dlx` means pnpm, `npx`
   npm, `bunx` bun, `yarn dlx` yarn), then npm.

| Flag           | What it does                                              |
| -------------- | --------------------------------------------------------- |
| `--overwrite`  | Replace files you changed.                                |
| `--dry-run`    | Show what would be installed and written, write nothing.  |
| `--no-install` | Update `package.json` but do not run the package manager. |

#### A theme from the theme generator

The [theme generator](/docs/theming/generator) ends with a command that holds the whole theme in
its link:

```sh
rectio add 'https://shironex.github.io/rectio/docs/theming/generator?theme=1.eyJi...'
```

Quote the link: most shells read `?` as a pattern. The CLI decodes the theme locally (nothing is
fetched from the link), derives and checks its colours with the same code the page runs, and writes
`styles/rectio/themes/<name>.css` in the shape of the shipped default theme, exactly the CSS the page
shows. The theme installs as `theme-<name>` (`theme-custom` unless you named it) with the font
packages it uses, and `rectio.lock.json` keeps its theme code. A bare code (`rectio add 1.eyJi...`)
works too.

The theme also takes over `:root`, so the app uses it at once; set `data-theme="<name>"` to name it
on a subtree. `rectio diff theme-<name>` compares your file with a rebuild of the theme, and
`rectio update` lists it when a rebuild would differ (a newer default theme or a newer CLI), with
the command that regenerates it.

### diff

Compares an installed item with the latest registry version.

```sh
rectio diff dialog
```

It lists each file as the same (`=`), changed (`~`) or missing (`✗`), marks the ones you edited since
install, and prints a unified patch from your file to the registry's.

### list

Lists registry items grouped by type, each with its version and title.

```sh
rectio list [--type component|block|theme|lib|hook|style|template] [--templates]
```

In a project, `✓` marks an installed item and `↑` one with a newer version available (`+` and `^`
in a terminal without UTF-8).

### search

Finds items by a word. Name matches come first, then title, category and description matches.

```sh
rectio search money
```

### update

Reports the installed items that have a newer version, then stops.

```sh
rectio update
```

It does not merge yet. Until it does, review a change with `rectio diff <item>`, then replace the
files with `rectio add <item> --overwrite`.

The merge it is designed to do: files you never edited are replaced outright; edited files get a
three-way merge between the locked version, the latest version and your file. Clean merges are
written, conflicts get standard markers and are listed, and the previous files are backed up first
so the update can be undone. The lock moves forward only for items that merged cleanly.

### mcp

Runs a read-only MCP server for coding agents. See [MCP server](/docs/mcp).

```sh
rectio mcp [--registry <url|folder>]
```

## Shared options

| Option             | What it does                                           |
| ------------------ | ------------------------------------------------------ |
| `--cwd <dir>`      | The project folder. Defaults to the current folder.    |
| `--registry <url>` | A registry URL or folder for this run.                 |
| `--verbose`        | `init`, `add`: list every item, file and package.      |
| `-q`, `--quiet`    | `init`, `add`: print only the result line, and errors. |
| `-h`, `--help`     | Show the help.                                         |
| `-v`, `--version`  | Show the version.                                      |

A command that fails prints one message and a hint, and exits with code 1.

## Output

`init`, `init --template` and `add` run as numbered steps. In a terminal each step spins while it
works and ends as one line with its time and a short note; a box closes the run with what was
added and what to run next:

```text
  rectio init  0.1.1

  template         saas-admin
  folder           my-admin
  theme            default
  package manager  pnpm

  ✓ [1/5] Checking project     0.2s  my-admin is free
  ✓ [2/5] Fetching template    0.2s  saas-admin 0.1.0, 73 files
  ✓ [3/5] Resolving items      0.5s  88 kit items
  ✓ [4/5] Writing files        0.0s  215 files
  ✓ [5/5] Installing packages  2.6s  pnpm, 9 packages
```

`add` sums the files up by folder and counts the dependencies it pulled in; `--verbose` lists every
item, file and package instead. A failed step names itself, its reason and the hint, and says
whether anything was written.

Progress and results go to stdout; errors, warnings and the update notice go to stderr. When stdout
is not a terminal, or in CI, the CLI prints plain `[2/5] Fetching template ... ok (0.2s)` lines with
no spinner and no box borders. `NO_COLOR` turns color off, `FORCE_COLOR` turns it on, and a locale
without UTF-8 gets ASCII marks.

## Registry URL

The CLI uses the first of:

1. `--registry`
2. the `RECTIO_REGISTRY_URL` environment variable
3. `registry` in `rectio.json`
4. `https://shironex.github.io/rectio/r`, the registry published with these docs

A plain folder or a `file://` URL works for development, as does the
[local registry server](/docs/registry#local-registry).

## Update notice

When a newer version of `@rectio/cli` is on npm, the CLI prints a short notice on stderr after the
command, with the version and how to get it. It asks npm at most once a day, caches the answer in
your user cache folder, and gives up after 1.5 seconds, so it never slows a command down or makes
it fail. A failed ask (offline, or npm without an answer yet) is tried again after an hour. It
stays quiet in CI, when stdout is not a terminal, and always in `rectio mcp`.

`pnpm dlx` keeps a downloaded package for a day, so a plain `pnpm dlx @rectio/cli` can run an older
copy. Started that way, the notice suggests `pnpm dlx @rectio/cli@latest` and says why.

Set `RECTIO_NO_UPDATE_CHECK=1` to turn it off.

`add` and `list` also say in one line when installed items have a newer version in the registry,
from the index they already fetched; `update` lists them.
