## Install

Blocks are part of rectio Pro: set `RECTIO_LICENSE_KEY` first. Without a key, `add` refuses and
writes nothing.

```sh
pnpm dlx rectio add expense-approval
```

The motion variant is `motion-expense-approval`. It installs the plain block too and changes only how the
block enters.

## Usage

The block holds only the selection and the reject dialog; decisions go to your callbacks. The
exported `approvalReducer` applies them with the allowed moves (decide a pending request, reopen
a decided one) and writes one audit event per request that changed, so a bulk action can never
reject an approved expense by accident.

A status filter above the list switches between the pending queue (the default), the approved
and rejected expenses, and all of them. Decided rows show who decided and when, the reason of a
rejection, and Reopen when you pass `onReopen`. Set `defaultStatus` to open on another view, or
`status` with `onStatusChange` to drive it from your router; `statusFilter={false}` hides it.

The block is data-agnostic: it takes plain records and calls you back; it never fetches. The Code
tab shows the preview's usage. The block's own source comes with the license.

## Messages

Every word the block prints, including what screen readers hear, comes from `messages`. The full
English defaults are exported as `EXPENSE_APPROVAL_MESSAGES`, typed as `ExpenseApprovalMessages`. Pass only the keys you
change; a message that counts or names a figure is a small function, so a language can order the
words and choose its plural form with `plural()`.

```tsx
import { plural } from '@rectio/blocks';

<ExpenseApproval
  requests={requests}
  events={events}
  currency="PLN"
  locale="pl-PL"
  onApprove={approve}
  onReject={reject}
  messages={{
    title: 'Akceptacja wydatków',
    approve: 'Zatwierdź',
    reject: 'Odrzuć',
    rejectManyTitle: (count) =>
      `Odrzuć ${count} ${plural(count, { one: 'wydatek', few: 'wydatki', many: 'wydatków', other: 'wydatku' }, 'pl-PL')}`,
  }}
/>;
```

A complete set typed as `ExpenseApprovalMessages` fails to compile when a key is missing.

## Logic

The money logic is exported and tested on its own, so a server can compute the same figures:
`approvalReducer`, `canTransition`, `reasonError` and `pendingTotal`.

## Accessibility

- Every checkbox and button names its expense; a rejection's reason is required and its error is tied to the field.
- On narrow widths the decision buttons sit under each expense at full touch size.
- Every figure is in tabular numerals with a true minus sign; negatives carry the sign as well as colour.
- Works in both themes, light and dark, at compact density and down to phone width with 44px touch targets.
- The motion variant moves only transform and opacity, plays once on first view and renders the plain block under reduced motion.
