The docs blocks are the pieces of a documentation site, built only from rectio components and
tokens, and independent of your framework and your MDX setup: the layout and navigation, prose and
MDX components, code blocks and tabs, an API reference, search, page navigation, switchers, a
feedback widget, a home page and a changelog.

## Plain and motion twins

Blocks that have something to animate have a motion twin with the same name and props. Pick per
block by import path:

```tsx
import { DocsToc } from '@rectio/blocks/docs'; // plain
import { DocsToc } from '@rectio/blocks/docs/motion'; // the marker glides
```

In the motion variants the table of contents glides its marker, code tabs glide their indicator,
the home page and releases fade up once on first view and feedback fades its thanks in. Reduced
motion renders the plain block. Blocks with nothing to animate are exported from the motion path
unchanged, so a page can import every block from one place.

## Content is data

Navigation, headings, releases and search results are props. Nothing here fetches: feedback takes
an `onSubmit`, search takes a provider, and you decide where each goes.

## Every word is a message

Each block takes a `messages` prop for the words it prints itself, including what screen readers
hear: the search dialog, the table of contents heading, the copy button, the pager, the feedback
question and the rest. The English defaults are exported beside each block (`DOCS_SEARCH_MESSAGES`,
typed `DocsSearchMessages`, and so on). Pass only the keys you change; a message that counts or
names a value is a small function, so a language can order the words and pick its plural form.

```tsx
<DocsSearch
  search={search}
  locale="en-GB"
  messages={{
    placeholder: 'Search the documentation',
    results: (count) => `Results: ${String(count)}`,
  }}
/>
```

Label props the blocks already had, such as `tocLabel` or `copyLabel`, still win when you pass
them.

## Syntax highlighting is token driven

The code block does not bundle a highlighter. It takes `tokens` from any build-time highlighter
and colours them through the theme's `--rx-code-token-*` variables, so light and dark themes
follow with no extra work. With shiki, for example, use
`createCssVariablesTheme({ variablePrefix: '--rx-code-' })`. Without tokens, pass plain `code`
and it shows in the foreground colour.

## One place for links

Every link in every block goes through `DocsLink`. Wrap your app in `DocsLinkProvider` with your
router's link component and every block follows; external links stay plain anchors that open in a
new tab.
