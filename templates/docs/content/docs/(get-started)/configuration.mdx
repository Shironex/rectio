Halyard reads `halyard.config.ts` from the project root. Every option has a default, so the smallest config is an empty object.

```ts title="halyard.config.ts"
import { defineConfig, redis } from '@halyard/core';

export default defineConfig({
  store: redis(process.env.HALYARD_URL),
  concurrency: 10,
  retries: { attempts: 3, backoff: 'exponential' },
  dashboard: { path: '/admin/jobs' },
});
```

## Environments

The config is code, so read what changes between environments from the environment. Keep the store URL out of the repository.

```ts title="halyard.config.ts" {4-6}
import { defineConfig, postgres } from '@halyard/core';

export default defineConfig({
  store: postgres(process.env.DATABASE_URL, {
    schema: process.env.NODE_ENV === 'test' ? 'halyard_test' : 'halyard',
  }),
});
```

<Callout type="note">
  Tests can use `memory()` as the store. It keeps jobs in the process and runs them as soon as they
  are added, so a test can assert on the result without a worker.
</Callout>

## Durations

Options that take a time accept milliseconds or a string: `'30s'`, `'5m'`, `'2h'`, `'1d'`. Strings are easier to read in a config and are checked by the type.
