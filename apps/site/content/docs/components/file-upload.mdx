## Install

```sh
pnpm dlx @rectio/cli add file-upload
```

`field` and `button` install with it.

## Usage

```tsx
import { Field, FieldDescription, FieldLabel } from '@/components/ui/field';
import {
  FileDropzone,
  FileItem,
  FileList,
  FileUpload,
  useFileUpload,
} from '@/components/ui/file-upload';

const upload = useFileUpload({
  upload: (file, { onProgress, signal }) => sendReceipt(file, onProgress, signal),
});

<Field>
  <FieldLabel>Receipts</FieldLabel>
  <FileUpload {...upload.rootProps} accept=".pdf,.png,.jpg" maxSize={10 * 1024 * 1024}>
    <FileDropzone />
    <FileList aria-label="Attached receipts">
      {upload.files.map((file) => (
        <FileItem key={file.id} file={file} />
      ))}
    </FileList>
  </FileUpload>
  <FieldDescription>PDF, PNG or JPG, up to 10 MB each.</FieldDescription>
</Field>;
```

The component sends nothing. `FileUpload` checks every picked or dropped file against `accept`,
`maxSize` and `maxFiles`, hands the ones that pass to `onFilesAdded`, and the ones that fail to
`onRejected`, each with a sentence such as "scan.pdf is 12.4 MB; the limit is 10 MB." The app owns
the list: it passes entries with a `status` (`queued`, `uploading`, `done`, `error`), a `progress`
from 0 to 100 and an `error` message, and gets `onRemove` and `onRetry` back.

`useFileUpload` keeps that list for you. Give it an `upload` function that resolves when the server
has the file and rejects with an Error the user can act on; it reports progress through
`onProgress` and should pass `signal` to `fetch`, which aborts when the user removes the file.
Without `upload`, files stay queued and you move them along with `updateFile`. Sizes are counted in
steps of 1024, so `10 * 1024 * 1024` reads as 10 MB.

Rejections are announced to screen readers. To keep them on screen as well, mark the Field invalid
and show them in a `FieldError`, as the demo does.

### Compact trigger

For a single avatar or attachment, use `FileUploadTrigger` in place of the dropzone. It is a
button with the same picker, rules and Field wiring, and takes dropped files too.

```tsx
<Field>
  <FieldLabel>Profile photo</FieldLabel>
  <FileUpload {...photo.rootProps} accept="image/png,image/jpeg" maxSize={2 * 1024 * 1024}>
    <FileUploadTrigger>Upload photo</FileUploadTrigger>
  </FileUpload>
</Field>
```

With `multiple={false}` the picker takes one file and `useFileUpload({ multiple: false })` replaces
the previous one.

### Progress bar

`FileProgress` is the bar the rows use, on Base UI's Progress. It works on its own for any transfer
with a known size; pass `value={null}` while the size is unknown.

The motion variant fades new rows up into place, lets removed rows fade out faster while the rows
below glide into the gap, settles the check in when an upload finishes, and lifts the dropzone's
icon while files are held over it. Use its `FileList` with its `FileItem`.

## Accessibility

- The dropzone and the compact trigger are real buttons: Tab reaches them and Enter or Space opens
  the native picker. The `FieldLabel` names them; the description and error are linked to them.
- While files are held over the dropzone, its border turns solid and its icon and text change, so
  the state never rests on colour.
- Added, rejected, removed, finished and failed files are announced in a polite live region.
- Each row states its status in words with an icon. The progress bar has `role="progressbar"`, is
  named after the file and carries `aria-valuenow`.
- Remove buttons are named after their file ("Remove invoice.pdf"), and Retry reads "Retry
  scan.pdf". After a remove, focus moves to the next row, or back to the dropzone.
- On touch screens the row buttons reach a 44px target.
