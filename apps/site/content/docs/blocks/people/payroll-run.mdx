## Install

```sh
pnpm dlx @rectio/cli add payroll-run
```

The motion variant is `motion-payroll-run`. It installs the plain block too.

## Usage

```tsx
import { PayrollRun } from '@/components/blocks/people/payroll-run/payroll-run';

<PayrollRun
  lines={lines}
  currency="GBP"
  period="November 2026"
  payDate={payDate}
  status={run.status}
  onApprove={approve}
  onPay={pay}
  onReopen={reopen}
/>;
```

The block does no payroll maths: your payroll system works out each line, and the block checks
and presents it. A line is `{ id, person, role?, gross, deductions, net, employerCost, bankAccount? }`
with every amount in minor units (pence, cents). Totals are added in integers, so they reconcile to
the unit.

A line blocks approval when its bank details are missing, its net pay is below zero, its net is
not gross less deductions, or an amount is not a whole number of minor units. The run shows how
many lines are flagged and why, and a filter lists only those. Approve stays disabled until every
line is clean, with the reason beside it.

The steps run review, approve, pay: approving and paying both ask first, and an approved run can
go back to review. Both are checked again when you confirm, so a line flagged while the dialog was
open stops it and shows the lines in the way. A flagged line shows in every status: Pay on an
approved run that picked up an issue holds back the same way Approve does. Negative gross,
deductions or employer cost, a line id used twice and totals past `Number.MAX_SAFE_INTEGER` (which
cannot be added to the unit) all block the run. `payrollPayouts(lines, payDate, currency)` turns the net pay into payouts for
the [Payouts](/docs/blocks/payouts) block.

## Logic

`reviewPayroll(lines)` gives the totals, the issues per line and whether the run is ready;
`issueCounts` and `payrollPayouts` run on the server too. See
[Rendering on the server](/docs/blocks/people#rendering-on-the-server) and
[Confirming](/docs/blocks/people#confirming).

## Accessibility

- A held back Approve or Pay button is described by the reason it waits, so a screen reader hears
  why.
- Each flag is a word on the line, never colour alone; a negative net is written with its sign.
- The steps are a list with the current step marked, and the confirm dialogs put the focus on the
  safe answer.
