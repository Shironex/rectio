A schedule adds a job to a queue at the times you give it. The job then runs like any other: with retries, a timeout and events.

```ts title="src/schedules.ts"
import { schedule } from '@halyard/core';
import { reports } from './queues/reports';

export const weekly = schedule(reports, {
  cron: '0 7 * * MON',
  timezone: 'Europe/Dublin',
  job: { kind: 'weekly-summary' },
});
```

## Time zones

A cron expression without a time zone runs in UTC. Give the zone your users live in, and a 7:00 schedule stays at 7:00 local time across daylight saving changes.

## Pause and resume <Badge>2.4</Badge>

Pausing keeps the schedule and its history. While it is paused no jobs are added; when it resumes, the next run is the next time on the schedule, and missed runs are skipped.

```ts
await weekly.pause();
console.log(await weekly.nextRunAt()); // null while paused
await weekly.resume();
```

<Callout type="tip">
  Paused schedules show in the dashboard with the time they were paused, so nobody wonders why the
  Monday report did not arrive.
</Callout>

## Overlapping runs

If a run is still going when the next one is due, the next one waits by default. Set `overlap: 'skip'` to drop it instead, or `overlap: 'allow'` to run both.
