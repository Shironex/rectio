## Install

```sh
pnpm dlx rectio add tag-input
```

`field` installs with it.

## Usage

```tsx
import { Field, FieldLabel } from '@/components/ui/field';
import { TagInput } from '@/components/ui/tag-input';

<Field>
  <FieldLabel>Vendor labels</FieldLabel>
  <TagInput
    value={labels}
    onValueChange={setLabels}
    max={6}
    validate={(tag) => (/^[a-z0-9-]+$/.test(tag) ? null : 'Use lower case letters and dashes.')}
  />
</Field>;
```

Enter or a comma turns the typed text into a tag; set `delimiters` for others, such as a semicolon
for email lists. Pasted text splits on the delimiters and on new lines, so a column copied from a
spreadsheet becomes one tag per row. Duplicates are turned away regardless of case unless you set
`caseSensitive`.

A rejected tag (a duplicate, one over `max`, or one your `validate` refuses) stays in the input for
the user to fix, and its message shows as the field's error, linked to the input and announced. A
`<Field invalid>` set by the app shows its own `FieldError` as with any input.

For a chip outside an input, such as the applied filters above a table, use `Tag` on its own. Give
it `onRemove` for a remove button named after its text.

TagInput has no motion variant. Tags are added from the keyboard, often many in a row, and an
animation on each would only slow typing down.

## Accessibility

- The input is named by its `FieldLabel` and linked to its description and error.
- Backspace in the empty input selects the last tag; a second Backspace removes it.
- Arrow Left from the start of the input moves into the tags, Arrow Right moves back out, and
  Delete or Backspace removes the tag in focus. Escape returns to the input.
- Each remove button is named after its tag ("Remove design"), so a list of them never reads as
  "Remove, Remove, Remove".
- A tag selected for removal fills with the accent, a change in lightness as well as colour, and
  the field keeps its focus ring.
- On touch screens the field is 44px tall and each remove button has a 44px target.
