## Install

```sh
pnpm dlx @rectio/cli add resizable
```

## Usage

```tsx
import { ResizableHandle, ResizablePanel, ResizablePanelGroup } from '@/components/ui/resizable';

<ResizablePanelGroup storageKey="invoices">
  <ResizablePanel id="invoice-list" defaultSize={35} minSize={25} maxSize={60}>
    {/* the list */}
  </ResizablePanel>
  <ResizableHandle label="Resize the invoice list" withGrip />
  <ResizablePanel id="invoice-detail" minSize={35}>
    {/* the open invoice */}
  </ResizablePanel>
</ResizablePanelGroup>;
```

Use resizable panels where people work in two or three views at once for a long time, such as a
list beside its detail. Sizes are percentages of the group; panels without a `defaultSize`
share what is left. Each panel stays within its `minSize` and `maxSize`, and so does its
neighbour, so a drag stops where either would break.

Drag a handle, or focus it and use the arrow keys (`keyboardStep` sets the step) and Home and End
for the limits. A double click puts every panel back to its default size.
`direction="vertical"` stacks the panels.

With `storageKey` the layout is kept in this browser and comes back on the next visit. Give each
panel an `id` too, so a saved size finds its panel when the page changes. A saved size outside a
panel's limits is pulled back inside them. The server draws the default sizes, and the browser
applies the saved layout right after hydration, so a page rendered ahead of time can shift once on
load; to avoid it, save the layout on the server with `onLayout` and pass it back as `defaultSize`.

On a phone, side by side panels are rarely right: show one view at a time and switch with tabs or
navigation.

## Accessibility

- Each handle is a focusable `separator` with `aria-valuenow`, `aria-valuemin` and
  `aria-valuemax` for the panel before it, and `aria-controls` pointing at that panel.
- Arrow keys along the direction resize; Home and End go to the limits. Right to left layouts flip
  the horizontal arrows.
- The hit area is wider than the line, and wider still on touch screens.
- A drag keeps the pointer captured, so it goes on when the pointer leaves the handle.
